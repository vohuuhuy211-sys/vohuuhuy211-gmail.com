# 产品规则

## 产品原则

1. 业务目标优先：实现必须能对应到任务中的用户价值和验收标准。
2. 根因优先：不得只掩盖现象；若只能临时缓解，必须明确标记限制和后续方案。
3. 真实可验证：不以假数据、静态演示、Mock（模拟）响应或无法复现的口头描述冒充完成。
4. 最小范围：只实现任务明确要求及其必要依赖，不顺便增加未经确认的功能。
5. 安全与隐私：最小化收集敏感数据；密钥不得写入代码、日志、任务文件或 Pull Request（拉取请求）。
6. 可恢复：高风险或不可逆操作必须有确认、备份或回滚方案。
7. 可访问与易理解：面向用户的提示应清晰说明发生了什么、影响和下一步，不暴露无意义的内部错误。

## 完成定义

一项任务只有同时满足以下条件才可标记完成：

- 范围内功能已形成真实代码或约定成果；
- 每条验收标准均有可复核证据；
- 相关测试已运行并保留日志；
- 生成文件和代码差异已被收集；
- 未完成项、假设和风险已披露；
- Pull Request 的必需状态检查全部通过且尚未由 Codex 擅自合并。
